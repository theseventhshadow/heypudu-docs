OBJETIVO DE DESPLIEGUE

El frontend React/Vite se despliega en Vercel.

Docker se utilizara para el backend y sus dependencias:

- PostgreSQL.
- ms-auth.
- ms-users.
- ms-posts.
- ms-interactions.
- ms-heypudu-rabbit-admin.

Por lo tanto, no es necesario incorporar el frontend al docker-compose.yml.

ARQUITECTURA (resuelta)

Flujo en produccion:

Usuario
  -> Frontend React desplegado en Vercel
  -> API Gateway HTTP API (HTTPS, ruta ANY /{proxy+})
  -> Application Load Balancer con HTTPS
  -> Microservicios backend en EC2 (Docker)
  -> PostgreSQL en Neon y S3

9. Reforzar la validacion de claves S3

Actualmente el backend genera claves aleatorias, pero acepta las claves
recibidas en las solicitudes sin comprobar completamente su pertenencia.

Antes de produccion se debe validar:

- Que avatarKey utilice el prefijo avatars/.
- Que audioKey utilice el prefijo audios/.
- Que coverImageKey utilice el prefijo covers/.
- Que la clave corresponda al usuario o a la publicacion que la utiliza.
- Que una clave no pueda reutilizarse para asociar el objeto de otro usuario.

La validacion debe realizarse en backend; la validacion del frontend no es
suficiente.

CONSIDERACIONES PARA EL FRONTEND

Los endpoints paginados devuelven Page<T> de Spring. El cliente debe
soportar una respuesta con content, totalElements, totalPages, number y
size, y enviar parametros como:

?page=0&size=20&sort=createdAt,desc

El endpoint GET /api/v1/posts tambien requiere JWT por la seguridad global.

El frontend debe llamar a /api/v1/auth/sync despues de autenticar al usuario.
No debe intentar crear perfiles mediante POST /api/v1/users, porque ese
endpoint publico no existe. La creacion interna se realiza mediante el flujo
de sincronizacion.

RESUELTO

1. Integracion S3 en ms-users

Implementado mediante:

- S3Config.java, que crea S3Client y S3Presigner.
- S3ServiceImpl.java, que genera URLs prefirmadas para avatares.
- Configuracion aws.s3.region y aws.s3.avatars-bucket.
- Endpoint POST /api/v1/users/me/avatar/presigned-url.
- URLs de descarga prefirmadas para perfiles y busquedas.
- Eliminacion del avatar anterior al reemplazarlo o quitarlo del perfil.

La URL de subida tiene una vigencia de 15 minutos y la URL de descarga
tiene una vigencia de 60 minutos.

2. Integracion S3 en ms-posts

Implementado mediante:

- S3Config.java, que crea S3Client y S3Presigner.
- S3ServiceImpl.java, que gestiona audio y portadas.
- Configuracion de buckets separados para audio y covers.
- Endpoint POST /api/v1/posts/audio/presigned-url.
- Endpoint POST /api/v1/posts/covers/presigned-url.
- URLs de descarga prefirmadas en las respuestas de publicaciones y feed.
- Eliminacion de audio y portada al eliminar una publicacion.

Las claves generadas utilizan los prefijos audios/ y covers/. La URL de
subida tiene una vigencia de 15 minutos y la URL de descarga tiene una
vigencia de 60 minutos.

3. Configuracion de AWS por entorno

Se agregaron variables para region y buckets en:

- application.yml.
- application-dev.yml.
- application-prod.yml.
- docker-compose.yml.

Las variables principales son:

- AWS_REGION.
- S3_AVATARS_BUCKET.
- S3_AUDIO_BUCKET.
- S3_COVERS_BUCKET.

4. Validacion basica de archivos

Los DTO PresignedUrlRequest validan que:

- fileName no este vacio.
- contentType no este vacio.
- Los avatares sean image/*.
- El audio sea audio/*.
- Las portadas sean image/*.

5. CORS en los microservicios

Los cinco microservicios ya tienen configuracion de CORS integrada con
Spring Security. La lista de origenes se controla mediante
APP_CORS_ALLOWED_ORIGINS y permite configurar el frontend local y el de
produccion sin utilizar * obligatoriamente.
